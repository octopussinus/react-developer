# Mobile app (Expo)

The mobile version of a web app built with react-dev, in its own repository.
Most of the code is the web app's, copied by `npm run port`; the screens are
translated to React Native one at a time. `PORT.md` says what is left.

## Run it in Expo Go

```bash
npm install
npm start          # then scan the QR code with Expo Go
```

**Which Expo Go?** This app targets **Expo SDK 57**. Expo Go only opens the SDK
it was built for:

- **Android phone or emulator** -- `npm start`, then press `a` (emulator) or scan
  the QR code; Expo CLI installs the matching Expo Go for you.
- **iPhone** -- the App Store's Expo Go may still be on an older SDK while Apple
  reviews the new one. Run `npx eas-cli@latest go` to put an Expo Go for SDK 57
  on your iPhone through TestFlight (needs an Apple Developer account), or use
  a development build (below).

Mocks are on in development: the phone answers every API request from the web
app's own MSW handlers, so no backend is needed. Set
`EXPO_PUBLIC_ENABLE_MOCKS=false` in `.env.local` to hit a real API -- and use
your computer's LAN address instead of `localhost`, which on a phone is the phone.

## Leaving Expo Go: a development build

Expo Go is a prebuilt app with a fixed set of native modules. The day you need
one it does not have (payments, maps, a native SDK), switch to a development
build -- your own Expo Go, with your modules in it. Nothing in the code changes.

```bash
npx expo install expo-dev-client
npx eas-cli@latest build --profile development --platform android   # or ios
# or, with Android Studio / Xcode installed locally:
npx expo run:android
```

Then `npm start` opens the app in the development build instead of Expo Go, and
you can drop `npm run expo-go:check` from `verify`. `ios/` and `android/` are
generated by `npx expo prebuild` and stay out of git -- configure native
behaviour in `app.json` and config plugins, never in those folders.

Store builds: `eas.json` already has `development`, `preview` and `production`
profiles (`npx eas-cli@latest build --profile production`).

## Keeping up with the web app

```bash
npm run port       # after any change on the web side
```

Copied files update themselves (unless you edited them here -- then PORT.md
lists them as diverged). Translated files are checked against the web file
they came from; when the web one changes, PORT.md marks the translation stale.
